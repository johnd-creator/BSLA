## Technical hierarchy contract

Root Registry admission and canonical BSR/IP keys precede traversal. Descendants
require exact upward retained-parent proof, bounded at 32 edges. Ancestors require
exact links from the registered root; selecting an ancestor exposes only the next
already-proven edge towards that root. Its page total is that branch's total, not
the parent's full child population. Cycles, missing edges and depth limits remain
explicit. Technical context does not become Registry membership or Engineering
write authority. No asset prefix, fuzzy match, Excel label or depth assigns a role.

The additive node_relation field distinguishes ROOT, DESCENDANT and ANCESTOR.
Ancestor pages contain only the root-bound branch. The scoped gateway validates
typed allowlisted nodes, root/path/parent/page proofs and response bounds, strips
unrelated fields and rechecks session and READ ledger before releasing data.
Off-root requests are denied without child counts or a protected body. Expiry and
revocation remain authoritative, including in-flight reads.

The UI labels PARTIAL coverage, unavailable unit as UNKNOWN and semantic role as
UNVERIFIED while the API role remains UNKNOWN. Source type/status are raw retained
values. A missing retained child is not a verified leaf. Opening the panel fetches
one bounded page; navigation loads one node at a time. Parent views explain their
branch restriction. Selected node/page/open state use same-origin history while
retaining framework metadata and unrelated asset-page parameters. No full tree is
eagerly fetched. Existing theme tokens, keyboard controls and scroll frames remain.
