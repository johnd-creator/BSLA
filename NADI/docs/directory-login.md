# Persiapan login direktori untuk Viewer

**Status: belum terhubung ke LDAP/Active Directory.** Adapter LDAPS untuk Microsoft AD telah disiapkan; belum pernah diaktifkan atau dihubungkan. Untuk pilot, port tetap 636, grup harus memberOf langsung (grup nested dan primary group tidak dihitung), dan pencarian satu username memakai sAMAccountName atau userPrincipalName. Identitas stabil: 16 byte objectGUID dari AD. Konfigurasi `NADI_DIRECTORY_ENABLED` default `false`; jangan aktifkan sebelum uji penerimaan. Selama OFF, akun lokal tetap memakai form dan kredensial semula. Belum ada migrasi database aktif, deploy, atau pengujian ke direktori perusahaan.

Hanya satu username dari form login yang dicari per percobaan. Tidak boleh ada sinkronisasi berkala, impor daftar pengguna, pencarian wildcard, atau pencocokan akun lokal lewat email, nama pengguna, maupun DN. Adapter wajib mewajibkan LDAPS atau StartTLS tanpa fallback plaintext dan memverifikasi CA serta hostname, menolak referral/redirect dan duplikasi hasil, memakai filter exact yang di-escape, menetapkan timeout dan batas hasil, menolak bind anonim/kata sandi kosong, dan memverifikasi kredensial serta keanggotaan grup yang dikonfigurasi sebelum mengembalikan satu stable ID kanonik. Realm dan definisi grup harus ditetapkan admin. Jangan menyimpan/log password, payload direktori atau token. Password harus dikirim utuh ke direktori, tanpa pemangkasan, setelah menolak kosong/hanya spasi.

Hanya identitas valid dengan keanggotaan grup persis yang bisa membuat Viewer saat login pertama. Yang disimpan yaitu hash realm + stable ID, identitas profil minimal internal dan role VIEWER. Tidak ada kata sandi direktori, email, nama atau data lain yang disalin; placeholder acak yang memenuhi skema DB tidak bisa dipakai lewat login lokal. Perubahan role/reset password melalui admin lokal tidak diizinkan untuk akun direktori. Viewer hanya bisa membuka sambutan tanpa data dan keluar. Sesi Viewer berakhir paling lambat 15 menit sejak autentikasi; tidak ada klaim pencabutan grup seketika. Nonaktifkan flag untuk menghentikan seluruh sesi direktori.

Sebelum penerimaan: siapkan ekstensi PHP LDAP/OpenLDAP (dukungan REQUIRE_SAN + TLS 1.2 minimum), FQDN DC sesuai SAN, file CA otoritatif, base DN yang sempit, attribute login, DN grup Viewer langsung, akun baca minimum dan secret dari deployment, HTTPS intranet, serta SESSION_SECURE_COOKIE=true. Variabel direktorinya tercantum dalam config/directory.php; jangan taruh secret di Git atau chat. Jika opsi TLS wajib tidak tersedia, login ditolak. PHP 8.5 upstream tidak mengekspor LDAP_OPT_X_TLS_REQUIRE_SAN; karena itu memasang ekstensi standar saja belum cukup. Terima runtime yang menegakkan SAN secara eksplisit dan uji penolakan CA salah dan hostname salah sebelum aktivasi. Akun pengguna juga perlu izin read atas sendiri untuk mengkonfirmasi GUID dan grup sesudah bind. Setelah disetujui, uji memakai akun uji resmi yang berada/tidak berada di grup, kredensial salah, TLS tidak valid, hasil ambigu, directory outage dan rekoneksi, dan sesi kadaluarsa. Baru jadwalkan migrasi kolom unik pada database yang benar setelah backup terverifikasi; jangan mengaktifkan dari lingkungan developer.

Bila runtime PHP yang disetujui tetap tidak menyediakan kontrol SAN tersebut, pilih profil OpenLDAP khusus yang terbukti menegakkan `TLS_REQSAN demand` dengan uji negatif terisolasi, atau identity broker AD resmi organisasi; penyesuaian integrasi dan persetujuan deployment tetap diperlukan. Jangan mengganti dengan CN-only, IP, plaintext, atau mematikan verifikasi TLS.
